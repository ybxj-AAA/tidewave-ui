About

How the work gets done

Every project starts with the same question: which decision is this screen asking for, and what happens when the user gets it wrong. The answer is usually fewer controls, not more, and states that are designed before the happy path.

I work inside the engineering team, in markup and tokens rather than static mockups, so a design survives its first sprint. Most of the projects above replaced a legacy interface while it stayed in daily use.
