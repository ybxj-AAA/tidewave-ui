Structure

Six blocks a product page usually needs.

Each one is a section you can delete. Nothing links to anything it doesn't need — pull out the testimonial and the page still closes properly.

Hero + product shot

A browser-chrome mock of your app. It renders whatever bars and boxes you put in it — nothing is fetched.

Feature grid

Six slots, auto-fit layout. Drop one and the row rebalances; nothing in the markup depends on the count.

Two split sections

Text beside a visual, with a mirrored variant. The right column in the first one is a highlight-marked code block.

Quote + FAQ

One pull-quote block and a native <details> accordion. No JS needed to open or close.

CTA band

A gradient close-out section with two buttons. The gradient is a token override, not a background image.

Footer

Four-column footer with a brand slot. Link targets are # placeholders you're expected to replace.

Getting started

Three files to read, in this order.

There's no build step, so "installing" it means copying a folder and opening a page. The work is deciding which sections survive.

  • Read tokens.css first. Colour, type, spacing and radius all come from here. Change five values and every page moves with you.
  • Then delete sections. Every block in these pages is self-contained markup. Removing the testimonial doesn't break the FAQ below it.
  • Finally replace the sample data. Every number on the dashboard page is hard-coded and labelled — swap it for your own output.

Where it's weakest

It won't design your product for you.

The layout is the part that's done. The copy, the screenshots, the actual value proposition — those are still yours, and they're what decides whether the page works.

If you don't have a product yet, these templates will make the absence more obvious, not less.

FAQ

Before you buy

Is this a working product or a template?

A template. It's static HTML and CSS with a small amount of JavaScript for theme switching, tabs and modals. There's no backend, no database, no accounts. The dashboard numbers are hard-coded samples.

Will it look like this once I add my content?

Roughly, yes — but the layout is tuned for short, specific text. Long marketing paragraphs will break the rhythm in the feature grid and the pricing cards. Keep your copy as tight as the samples.

Do I need a build step or npm?

No. Copy the folder, open index.html. If you want to deploy it, any static host works — GitHub Pages, Netlify, Cloudflare Pages, an S3 bucket.

How do I change the colours?

Edit the semantic aliases at the top of tokens.css. Components never reference raw hex values, so nothing else needs to change. Dark mode is a second token block on the same file.

What about accessibility?

Focus outlines are styled, modals move focus on open, the tab group uses role="tablist", and prefers-reduced-motion is respected. It has not been through a formal WCAG audit — treat it as a reasonable starting point, not a certificate.

Look at the pages. That's the whole preview.

Every page in this repo is exactly what you get — no lite version, no locked sections. If it looks right here, it'll look right in your repo.
